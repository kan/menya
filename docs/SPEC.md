# 麺屋クリッカー 仕様書

スマホで遊ぶラーメン版クッキークリッカー。スープ・麺・具を指で作り、丼をタップしてラーメンにする。売上で弟子を雇って段々と自動化し、材料の流れを管理するリソース管理要素へ広げていく。

- 対象：スマホのブラウザ（縦画面・タッチ操作が前提）
- 公開先：`menya.kan-game.app`（リポジトリは kan/menya）。技術構成は kan/pujan・kan/tako-sen と同じ（`AGENTS.md`）
- この文書の数値はプロトタイプ時点の初期値。バランス調整で変わる前提で、コード上は設定表にまとめる（→「11. 数値の初期値」）
- 「未決定」と書いた項目は、実装前に決める

---

## 1. 用語

| 用語 | 意味 |
|---|---|
| 材料 | スープ・麺・具（焼豚）の3種類 |
| 在庫 | 材料ごとの手持ち数 |
| 置き場（枠） | 材料ごとの在庫の上限 |
| 丼 | 材料を使ってラーメンを作る場所。タップで作る |
| 献立 | ラーメンの種類（正油・塩・味噌・とんこつ） |
| 杯数 | 作ったラーメンの数。**通算**（減らない） |
| 売上 | 所持金。ラーメンを作ると増え、強化に使うと減る |
| 通算売上 | これまで得た売上の合計（使っても減らない） |
| 弟子 | 材料または献立ごとに自動生産する人手。雇うのは最初の1回払いのみで、維持費はない |
| 店主 | プレイヤー自身。鍛えると手作業の生産量が増える |
| 帳場 | 店主・献立・実績・暖簾分け（・ランキング）をまとめた画面 |
| 暖簾分け | 強くてニューゲーム（プレステージ） |

## 2. 画面構成

1画面に収まる縦レイアウト。上から次の順に並べる。

1. **ヘッダー**：店名の縦書き看板、作ったラーメンの杯数（総合・通算。数字の後ろに小さく「杯」）、売上（「売上 12,800円」）、帳場ボタン（店主レベルを表示）
2. **調理タブ**：スープ／麺／具。各タブに在庫「n / 上限」を表示。どれか1つの調理画面だけを表示する
3. **調理画面**（表示中のタブの材料）
   - 操作エリア（画面の大部分）
   - **ゲージ行**：「スープ 7/10」＋溜まり具合のバー（上限で100%、満杯で赤）＋「枠+」ボタン
   - **弟子の行**：「弟子 5人 Lv3」「1分で約○個」＋［増やす］［鍛える］
4. **丼エリア**
   - 献立ボタン（解禁済みは名前・値段・その献立の盛り付け弟子の人数。未解禁は「？？？」と必要実績数）
   - 丼（タップでラーメンを作る）、材料ごとの在庫と、選択中の献立の必要数（×2 など）
   - 盛り付け弟子の行（選択中の献立のもの）：［増やす］［鍛える］
5. **帳場シート**（下から出る）：店主／献立／実績／暖簾分け／ランキング（追加予定）

通知：
- 生産・売上は、その場から浮き上がる文字で出す（「スープ +1」「+800円」「一丁あがり！」）
- 実績解除・献立解禁・暖簾分けなどは、上部のトーストで出す（順番に表示）
- 別のタブで強化が買えるようになったら、そのタブに点を付ける。帳場には「店主を鍛えられる／未確認の実績がある／暖簾分けで暖簾が増える」ときに点を付ける

## 3. 手作業

### 3.1 材料づくり

| 材料 | 操作 | 1回の条件 |
|---|---|---|
| スープ | 鍋の上で指をぐるぐる回す | **1.5周**で1回。右回り・左回りどちらでもよく、途中で向きを変えても回した角度を合算する。鍋の中心から一定距離（24px）以内の動きは数えない |
| 麺 | タップ | **1タップ**で1回 |
| 具 | **上から下へ**のスワイプ | 指を置いてから下方向に60px以上動いたら1回。**1回指を置くごとに最大1回**。上方向（戻す動き）は数えない |

- 1回の作業でできる個数＝**店主のレベル**（Lv1なら1個）
- 置き場が満杯なら作れない（「もう置けない（○個まで）」と表示し、進捗は進まない）
- スープの渦は、手で回した角度にそのまま追従して回る

### 3.2 丼でラーメンを作る

- 丼に材料を入れる操作はない。**丼をタップすると、選択中の献立の必要数を在庫から使ってラーメンができる**
- 1タップで作れる杯数＝最大で**店主のレベル**まで（材料が足りる分だけ）
- できたら杯数（総合・献立別）と売上が増える。売上は即時に入る（客の待ちなどの要素は無し）
- 材料が足りないとき：丼が揺れて「○○が足りない」と表示し、**足りない材料のタブに自動で切り替える**（複数ならスープ→麺→具の順で最初のもの）
- 材料がそろっている間は、丼に中身が入って光る。スープの色は献立ごとに変える

## 4. 自動化（弟子）

### 4.1 材料の弟子（スープ・麺・具 共通）

3材料とも**同じ仕組み・同じ数値**。調理画面のゲージ行と弟子の行から強化する。

| 強化 | 効果 | 置き場所 |
|---|---|---|
| 増やす | 弟子+1人。時間で材料が自動で増える | 弟子の行 |
| 鍛える | その材料の弟子全員の効率が上がる。**レベルが上がると雇う額も上がる** | 弟子の行 |
| 枠を広げる | 置き場の上限が増える（放置向け） | ゲージ行の右端 |

- 雇うのは1回払い。時給などの維持費はない
- 置き場が満杯の間は弟子は止まる（「置き場がいっぱいで休憩中」）
- 弟子が0人のときは「鍛える」は押せない
- 「鍛える」ボタンには、1分あたりの生産数（今→次）と雇う額（今→次）を表示し、トレードオフが見えるようにする
- 弟子がいる間のアニメーション：スープは渦がひとりでに回る。麺・具は包丁が一定のリズムで動く（人数が多いほど速い、満杯なら止まる）

### 4.2 盛り付け弟子（献立ごと）

- **献立ごとに配置する**。正油の弟子は正油だけ、塩の弟子は塩だけを作る
- 選択中の献立とは無関係に、それぞれ自分の献立を作り続ける。**献立を切り替えても、勝手に別の献立が作られることはない**
- **レベルは全献立で共通**。「鍛える」で全献立の盛り付け弟子が速くなる
- 雇う額は献立の値段に比例する
- 材料が足りないと止まり、「麺・具待ち」のように不足分を表示する
- 複数の献立の弟子は同じ在庫を取り合う（処理順は献立の並び順）
- 盛り付け弟子に「枠を広げる」は無い

### 4.3 バランスの方針

- 序盤は、**材料の弟子＋安い枠で材料を多めに溜め、戻ってきて丼をまとめてタップする**のが無駄のない遊び方になるようにする
- 盛り付けの自動化と速度アップは**重め**（高額・低速）にし、中盤以降の目標にする
- 材料ごとの差は設けない。違いは献立の材料比率で出す

## 5. 店主（作業派向け）

- 帳場の「店主」ページで鍛える
- 店主レベル＝手作業1回でできる材料の数＝丼1タップで作れる最大杯数
- 店主ページには、手作業の通算記録（スープ○個・麺○個・具○個・丼○杯）も表示する

## 6. 献立

| 献立 | スープ・麺・具 | 値段 | 解禁条件 |
|---|---|---|---|
| 正油 | 1・1・1 | 800円 | 最初から |
| 塩 | 2・1・1 | 1,200円 | 実績5個 |
| 味噌 | 1・2・1 | 1,250円 | 実績15個 |
| とんこつ | 2・1・3 | 2,000円 | 実績30個 |

- 後の献立ほど材料1個あたりの単価が少し高い
- 丼エリアの献立ボタン、または帳場の「献立」ページで選ぶ。選択中の献立が丼タップで作られる
- 画面上の杯数は全献立の**総合**。献立ごとの杯数も別に保持し、実績とランキングに使う
- 未解禁の献立は「？？？」と必要な実績数を表示する

## 7. 実績

クッキークリッカーのように多数用意し、**解除数で献立を解禁**する。プロトタイプは67個。

| グループ | 内容 | 数 |
|---|---|---|
| 杯数 | 通算 1, 10, 50, 100, 500, 1,000, 5,000, 1万, 5万, 10万杯 | 10 |
| 献立 | 献立ごとに 10, 100, 1,000杯 | 12 |
| 売上 | 通算売上 1万, 10万, 100万, 1,000万, 1億円 | 5 |
| 手作業 | スープ・麺・具・丼を手で 100回, 1,000回 | 8 |
| 弟子 | 材料3種＋盛り付け（全献立合計）の人数 1, 10, 25人、レベル 5, 10 | 20 |
| 置き場 | 材料ごとに上限 20, 50 | 6 |
| 店主 | Lv 3, 5, 10 | 3 |
| 暖簾分け | 1, 3, 10回 | 3 |

- 各実績には名前（「開店の一杯」「行列のできる店」など）と条件文を持たせる
- 帳場の「実績」ページで一覧できる。解除済みは強調し、未解除は名前を薄く表示（条件文は見せる）
- 一度解除した実績は、暖簾分けしても残る
- 古い保存データから引き継いだ時点で満たしている実績は、通知を出さずにまとめて解除する

## 8. 暖簾分け（強くてニューゲーム）

- 店を弟子に譲って、新しい店を一から始める
- **リセットされるもの**：売上（所持金）、在庫、手作業の進捗、全弟子と全レベル、置き場、店主レベル
- **残るもの**：実績、献立の解禁、通算杯数（総合・献立別）、通算売上、手作業の記録、暖簾の枚数、暖簾分けの回数、選択中の献立
- 暖簾の枚数 = floor( √(通算売上 ÷ 50万円) )。50万円で1枚、200万円で2枚、450万円で3枚…
- 暖簾1枚につき、全献立の売上が+10%
- 暖簾分けで増える枚数が1以上のときだけ実行できる。帳場には「いま暖簾分けすると +○枚」または「次の暖簾まであと○円」を表示する
- 実行は2回押して確定する（誤操作防止）
- これとは別に「データをすべて消す」（実績・暖簾も消える）を用意する。これも2回押しで確定

## 9. ランキング（追加予定）

### 9.1 内容

- **週単位**で、ユーザーごとの**杯数**を競う
- 種類は2つ：
  - **総合**：全献立の合計杯数
  - **献立別**：献立ごとの杯数
- 献立別ランキングは、**自分が解禁している献立のものだけ**見られる
- 帳場に「ランキング」ページを追加して表示する（タブを5つにするか、別の入口にするかは未決定）

### 9.2 集計の考え方

- 週ランキングの値は、その週に作った杯数（週の開始時点からの増分）。画面上の通算杯数とは別に、週ごとの杯数を記録する
- 手作業・弟子のどちらで作った杯も数える
- 暖簾分けをしても、その週の杯数は減らない（通算杯数と同じく残る）

### 9.3 決まっていること（技術構成から）

- ユーザーの識別は kan-game.app の ID（kan/game）を使う。名前・退会も kan-game.app と共通
- ランキングの記録と集計は backend（Cloudflare Workers ＋ D1）で行う
- ID や名前がなくても遊べる。ランキングに参加するときだけ ID と名前を使う

### 9.4 未決定

- 週の区切り（pujan・TAKO-SEN に合わせて日本時間の月曜0:00 が候補）
- ランキングに載せる条件（名前の登録と公開への同意を求めるか。pujan は両方を求めている）
- 記録を送るタイミング・頻度
- 不正対策（ありえない生産速度の検出、クライアント値をどこまで信じるか）
- 表示件数（上位○位＋自分の順位、など）と、過去の週の結果を見られるか
- 週の上位者への報酬の有無
- 遊びの保存はブラウザ内（localStorage）のまま、ランキング用の週の杯数だけを送るか、進行そのものもサーバーに持つか

## 10. 保存

- プロトタイプではブラウザの localStorage に保存（数秒おき・画面を離れたとき・主要な操作の後）
- 保存データにはバージョン番号を持たせ、形式を変えたときは旧データから引き継ぐ処理を書く（前の版で遊んだ杯数・売上・弟子を失わせない）
- 読み込み時、上限を超える在庫は上限に切り詰める

## 11. 数値の初期値

すべて設定表にまとめ、コードの他の場所に数値を直書きしない。

### 材料の弟子（3材料共通）

| 項目 | 値 |
|---|---|
| 生産速度 | 1人・Lv1で10秒に1個（0.1個/秒） |
| 雇う額 | 2,000円 ×1.15^(人数) ×(1 + 0.3×(Lv−1)) |
| 鍛える効果 | Lvごとに効率+50%（速度 × (1 + 0.5×(Lv−1))） |
| 鍛える額 | 3,000円 ×1.9^(Lv−1) |
| 置き場 | 初期10、1回ごとに+10 |
| 枠を広げる額 | 400円 ×1.45^(広げた回数) |

### 盛り付け弟子（献立ごと・レベル共通）

| 項目 | 値 |
|---|---|
| 生産速度 | 1人・Lv1で20秒に1杯（0.05杯/秒） |
| 雇う額 | 3万円 ×(献立の値段÷800、千円単位に丸め) ×1.25^(その献立の人数) ×(1 + 0.3×(Lv−1))<br>（正油 3万円・塩 4.5万円・味噌 4.7万円・とんこつ 7.5万円から） |
| 鍛える効果 | Lvごとに効率+50% |
| 鍛える額 | 6万円 ×2.2^(Lv−1) |

### 店主

| 項目 | 値 |
|---|---|
| 効果 | 1回の作業で Lv 個、丼1タップで最大 Lv 杯 |
| 鍛える額 | 3,000円 ×2.4^(Lv−1) |

### 暖簾分け

| 項目 | 値 |
|---|---|
| 暖簾の枚数 | floor(√(通算売上 ÷ 500,000)) |
| 効果 | 1枚につき売上+10% |
